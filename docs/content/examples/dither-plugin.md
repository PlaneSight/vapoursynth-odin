# Output formats and frame allocation

The dither example demonstrates a plugin whose output format differs from its
input. Read the [invert example](invert-plugin.md) first for the callback
lifecycle. Here the binding lessons are format negotiation, output allocation,
sample representation, and ownership when constructing a new frame.

The conversion uses a checked-in blue-noise tile. The quantizer gives the frame
API a concrete workload; this guide focuses on the VapourSynth integration.

## Run the example

From the repository root:

```console
uv run tools/examples.py build dither
uv run tools/examples.py check --no-build dither
```

For an optional visual check:

```console
uv run --group preview tools/examples.py preview --no-build dither
```

The [build guide](../guides/previewing-examples.md) explains platform prerequisites
and how to copy the example into a separate project.

## Follow the binding calls

| Stage | API usage | Responsibility |
| --- | --- | --- |
| Registration | `configPlugin`, `registerFunction` | Publish the entry point and argument signature |
| Construction | `mapGetNode`, `getVideoInfo`, map property accessors | Acquire the input reference and validate its format and arguments |
| Format negotiation | `queryVideoFormat` | Obtain an output format with the intended storage depth and subsampling |
| Filter creation | `createVideoFilter2` | Publish the output video information, dependency, callbacks, and instance state |
| Initial activation | `requestFrameFilter` | Declare the required upstream frame |
| Ready activation | `getFrameFilter`, `newVideoFrame` | Acquire the source and allocate an output using it as the property source |
| Plane access | `getReadPtr`, `getWritePtr`, `getStride`, plane dimensions | Process active samples using each plane's independent layout |
| Completion and teardown | `freeFrame`, `freeNode` | Release acquired references and retain only the output transferred to the host |

Construction validates a constant integer format before publishing a filter.
The output video information preserves dimensions and timing while replacing
the format. Plane dimensions come from the actual frame, so subsampled chroma
must not be processed as if it had luma dimensions.

The frame callback treats source and destination strides independently. A
16-bit input may produce an 8-bit output: the pointer type and bytes consumed
per sample must follow each frame's own format. Row padding is not image data.
See [frame layout](../guides/frames.md) for the underlying contracts.

Each instance retains one source-node reference and immutable conversion data.
Each callback releases the source frame it acquires. The completed output is
transferred to VapourSynth; failures report a filter error and release resources
already acquired. These are the ownership rules to preserve when adapting the
example to another operation.

## Effective depth and storage depth

The example accepts integer Gray, RGB, and YUV with 8–16 bit input samples.
`bits` selects an effective depth from one through the input depth. The output
uses `max(8, bits)` bits of storage, so sub-eight-bit demonstrations still return
ordinary VapourSynth frames.

| Effective depth | Stored values in an eight-bit sample |
| ---: | --- |
| 1 | 0, 255 |
| 2 | 0, 85, 170, 255 |
| 4 | 0, 17, 34, …, 255 |

This distinction demonstrates that a format's storage depth and the values an
algorithm chooses to write are separate concerns. Zero bits is rejected.
At unchanged depth, the example returns the input node reference directly.

The preview uses `scale=1` for these low-bit RGB views, mapping the full source
interval to the selected levels. The default `scale=0` uses power-of-two code
scaling. Neither mode interprets color metadata or performs a range conversion.
`seed` selects a tile phase; `simd` chooses an equivalent processing path and
does not change the binding calls or output contract.

The row-processing code remains in the example's `src/` directory. The maintained
`uv run tests/advanced.py` suite checks format boundaries, output samples, source
immutability, properties, and concurrent frame requests. Use it when changing
the example's binding calls or memory access.
